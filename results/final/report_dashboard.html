AI의 답변, 어디까지 믿어도 될까?

노트북 GPU 한 대에서 돌아가는 작은 AI(3~4B)를 이용해, 금융 답변이 실제 공시 근거와 맞는지 검증하는 실험을 해봤다. 무엇을 발견했는지 쉬운 말로 정리했다.

06

진행하며 만난 두 가지 한계

한계 1

"정보가 없다"와 "명백히 틀렸다"를 헷갈린다

공시 자료에 애초에 관련 내용이 없는 경우와, 있는데 답변이 그걸 반박하는 경우를 잘 구분하지 못했다. 프롬프트를 두 가지 방식으로 고쳐봤지만 도움이 안 됐고, 오히려 기존에 잘 맞히던 것까지 흔들리는 부작용이 있어 포기했다.

한계 2

여러 조건 중 "언급 안 된 조건"을 못 찾는다

위 e-그린세이브예금 사례처럼, 조건 A·B를 모두 만족해야 하는데 답변이 A만 언급하면, 그것만 보고 "맞다"고 승인하는 경향이 있었다. 모델을 훨씬 키워도(130배 큰 모델) 똑같이 놓쳤다.

Qwen 3.5-4B — 0 / 2 Claude Haiku (참고, 훨씬 큰 모델) — 1 / 2 Nemotron Ultra 550B (참고, 훨씬 큰 모델) — 0 / 2
07

끝내고 나서 스스로 다시 검증했다

프로젝트를 마친 뒤, 평가 방식 자체에 허점이 없는지 점검하는 도구를 만들어 이 프로젝트에 다시 적용하고, 같은 실험을 모델 4개에 다시 돌렸다. 바로 위 두 한계에 대한 판단이 모두 바뀌었다.

한계 1 · 정정

태스크가 어려운 게 아니라, 고른 모델의 특성이었다

"정보가 없다"를 가려내는 능력은 모델 크기 순서를 따르지 않았다. 탈락시켰던 3B 모델은 4문항을 전부 맞혔고, 550B 모델은 하나도 못 맞혔다. 태스크 자체의 한계라고 결론지었던 게 틀렸다.

Kanana 3B (탈락) — 4 / 4 Claude Haiku — 4 / 4 Claude Sonnet — 4 / 4 Qwen 3.5-4B (채택) — 0 / 4 Nemotron 550B — 0 / 4
한계 2 · 정정

"조건이 빠진 걸 못 본다"가 아니라 "조건 관계를 구분 못 한다"

조건을 하나씩 세어 대조하도록 지시하자 놓치던 것을 잡아냈다. 그런데 하나만 충족해도 되는 조건까지 "빠졌다"고 보고 정상 답변을 거부했다. 즉 병목은 누락 탐지가 아니라, 여러 조건이 "전부 필요"한지 "하나만 충족하면 되는지"를 구분하는 능력이었다. 조건 관계를 구분할 수 있는 더 큰 모델에서는 같은 지시가 오히려 성능을 올렸다.

채택한 방식
지금의 검증 지침
  • 위험한 답변을 놓친 비율 11.1%
  • 정상 답변을 통과시킨 비율 91.3%
더 엄격한 방식
조건을 하나씩 세어 대조하도록 지시
기각
  • 위험한 답변을 놓친 비율 11.1% → 5.6%
  • 정상 답변을 통과시킨 비율 91.3% → 67.4%
새로 찾은 문제

"위험한 답변을 덜 놓치는데 왜 안 쓰나?" — 평가 기준 자체가 불완전했다

이 프로젝트는 "위험한 답변을 놓치지 않는 것"을 1순위로 두고 지표를 정했다. 그런데 그 목록에 "정상 답변을 막지 않는 것"을 재는 자리가 없었다. 그래서 1순위만 보면 더 엄격한 방식이 "개선"으로 보인다 — 실제로는 정상 답변 3건 중 1건을 막는데도(거부율 8.7% → 32.6%). 극단적으로는 무조건 "틀렸다"고만 답하는 껍데기가 1순위 지표에서 만점을 받는다. 목표를 순위가 아니라 조건으로 바꿔야 한다 — "위험한 답변은 줄이되, 정상 답변을 막는 비율은 나빠지지 않는다."

→ 안전하기만 하고 정상 답변을 막는 검증기는 쓸 수 없다. 이 지침은 채택하지 않았다.

08

예상 밖의 발견 — 더 작은 모델인데 더 느렸다

가볍게 압축한 버전이라 당연히 더 빠를 거라 예상했는데, 실측해보니 오히려 더 느렸다. 원인은 모델이 아니라 서버가 실제 사용 패턴보다 훨씬 큰 동시 처리 용량을 잡아둔 것이었다 — 실제로는 검증 요청이 한 번에 하나씩 들어오는데, 서버는 수백 개를 동시에 받을 준비를 하고 있었다. 이 값을 실제 사용량에 맞게 줄이자 GPU의 반복 연산 가속 기능이 정상적으로 켜졌다.
